# 测试自动化综合实战

上一步：[[01-技术基础/Python/测试自动化基础/06-Allure测试报告基础|06-Allure测试报告基础]]

> [!abstract] 实战目标
> 建立一个最小但结构完整的 pytest 项目：requests 负责接口测试，Playwright 负责网页测试，Allure 保存报告证据。示例只访问公开演示网站，不包含生产写入。

## 1. 创建项目

```powershell
New-Item -ItemType Directory -Force -Path 'D:\python-test-lab' | Out-Null
Set-Location 'D:\python-test-lab'
python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install pytest requests pytest-playwright allure-pytest
python -m playwright install chromium
```

## 3. 配置文件

`config/settings.py`：

```python
import os


API_BASE_URL = os.getenv("API_BASE_URL", "https://httpbin.org")
WEB_BASE_URL = os.getenv(
    "WEB_BASE_URL",
    "https://www.selenium.dev/selenium/web/web-form.html",
)
REQUEST_TIMEOUT = float(os.getenv("REQUEST_TIMEOUT", "10"))
```

这里提供的是安全公开默认值。企业项目中的地址应通过 CI 变量或环境配置注入。

## 4. pytest 配置

`pytest.ini`：

```ini
[pytest]
testpaths = tests
addopts = -ra
markers =
    api: 接口测试
    web: 网页测试
    smoke: 冒烟测试
```

## 5. 公共 fixture

`conftest.py`：

```python
import pytest
import requests


@pytest.fixture(scope="session")
def api_session():
    session = requests.Session()
    session.headers.update(
        {
            "Accept": "application/json",
            "User-Agent": "python-test-lab/1.0",
        }
    )
    yield session
    session.close()
```

Playwright 的 `page` fixture 由 `pytest-playwright` 自动提供，不需要自己创建浏览器。

## 6. 脱敏工具

`utils/sanitize.py`：

```python
SENSITIVE_HEADERS = {
    "authorization",
    "cookie",
    "set-cookie",
    "x-api-key",
}


def sanitize_headers(headers: dict) -> dict:
    return {
        key: "***" if key.lower() in SENSITIVE_HEADERS else value
        for key, value in headers.items()
    }
```

## 7. requests 接口用例

`tests/api/test_httpbin.py`：

```python
import json
import allure
import pytest

from config.settings import API_BASE_URL, REQUEST_TIMEOUT


@allure.epic("自动化入门")
@allure.feature("HTTP 接口")
@pytest.mark.api
@pytest.mark.smoke
def test_get_query_parameter(api_session):
    params = {"name": "alice", "source": "pytest"}

    with allure.step("发送 GET 请求"):
        response = api_session.get(
            f"{API_BASE_URL}/get",
            params=params,
            timeout=REQUEST_TIMEOUT,
        )

    with allure.step("检查 HTTP 和业务结果"):
        assert response.status_code == 200
        body = response.json()
        assert body["args"] == params

    allure.attach(
        json.dumps(body, ensure_ascii=False, indent=2),
        name="safe-response.json",
        attachment_type=allure.attachment_type.JSON,
    )


@pytest.mark.api
@pytest.mark.parametrize("status_code", [200, 404, 500])
def test_expected_status(api_session, status_code):
    response = api_session.get(
        f"{API_BASE_URL}/status/{status_code}",
        timeout=REQUEST_TIMEOUT,
    )
    assert response.status_code == status_code
```

## 8. Playwright Page Object

`pages/web_form_page.py`：

```python
from playwright.sync_api import Page, expect


class WebFormPage:
    def __init__(self, page: Page):
        self.page = page
        self.text_box = page.get_by_label("Text input")
        self.submit = page.get_by_role("button", name="Submit")
        self.message = page.locator("#message")

    def open(self, url: str):
        self.page.goto(url)

    def submit_text(self, text: str):
        self.text_box.fill(text)
        self.submit.click()

    def assert_success(self):
        expect(self.message).to_have_text("Received!")
```

## 9. Playwright 测试

`tests/web/test_web_form.py`：

```python
import allure
import pytest
from playwright.sync_api import Page

from config.settings import WEB_BASE_URL
from pages.web_form_page import WebFormPage


@allure.epic("自动化入门")
@allure.feature("网页表单")
@pytest.mark.web
@pytest.mark.smoke
def test_submit_web_form(page: Page):
    form = WebFormPage(page)

    with allure.step("打开表单"):
        form.open(WEB_BASE_URL)

    with allure.step("输入并提交"):
        form.submit_text("Playwright")

    with allure.step("验证提交成功"):
        form.assert_success()

    allure.attach(
        page.screenshot(full_page=True),
        name="web-form-result",
        attachment_type=allure.attachment_type.PNG,
    )
```

## 12. 执行测试

全部：

```powershell
python -m pytest -v
```

只执行接口：

```powershell
python -m pytest -m api -v
```

只执行网页并显示浏览器：

```powershell
python -m pytest -m web --headed -v
```

失败时保留 Trace：

```powershell
python -m pytest -m web --tracing retain-on-failure
```

生成 Allure 数据：

```powershell
python -m pytest --alluredir allure-results --clean-alluredir
```

查看报告：

```powershell
allure serve allure-results
```

## 13. 如何判断测试真的有效

不要只看命令退出码和 Allure 绿色状态，还要确认：

- 用例是否真的被收集；
- 请求是否发往预期环境；
- 输入是否是本次生成的数据；
- 断言是否检查业务字段；
- 页面测试是否检查用户可见结果；
- 失败是否能保留足够证据；
- 用例是否可以单独重复运行；
- 是否没有依赖执行顺序。

## 14. 故意制造失败学习报告

把接口断言临时改成错误值：

```python
assert response.status_code == 201
```

执行后观察：

- pytest 失败堆栈；
- Allure 中的失败步骤；
- 请求响应附件；
- 失败发生在准备、执行还是断言阶段。

学习完成后恢复正确断言。

## 15. 从 Demo 走向真实项目

建议逐步增加：

1. 多环境配置；
2. 测试账号和凭据注入；
3. 动态数据工厂；
4. API Client；
5. Page Object；
6. 失败证据；
7. 并行执行；
8. CI 流程；
9. 数据清理；
10. 报告访问控制。

不要一开始就搭建过度复杂的框架。先让一条 API 和一条 Web 流程稳定、可重复、证据完整，再抽象公共层。

## 16. 最终验收清单

- [ ] 新环境可以按 requirements 安装
- [ ] API 用例可以独立运行
- [ ] Web 用例可以独立运行
- [ ] 所有请求有超时
- [ ] 用例不包含真实密钥
- [ ] 测试数据不依赖固定共享记录
- [ ] 失败有响应或截图证据
- [ ] Allure 报告不混入旧结果
- [ ] Trace 和报告有访问控制
- [ ] 测试结论区分框架验证与真实业务验收
